# Secret inventory (operator-provided)

No secrets are committed. The chart references secrets **by name** via
`existingSecret` fields so you can create them with `kubectl`, Sealed Secrets,
External Secrets, or SOPS. Templates: `manifests/operator-secrets/`.

| Secret (default name) | Required? | values path | Keys | Purpose |
| --- | --- | --- | --- | --- |
| `jama-license` | **Yes** | `license.existingSecret` | `license.yaml` | Jama entitlement (mounted into `core*`) |
| `jama-db` | **Yes** | `database.existingSecret` | `username`, `password` (`database.usernameKey`/`passwordKey`) | External DB auth |
| `jama-registry` | **Yes** (licensed registry) | `global.imagePullSecrets[]` / `imagePullSecret.*` | `.dockerconfigjson` | Pull Jama images |
| `jama-tls` | If `ingress.tls.enabled` and not cert-manager | `ingress.tls.secretName` | `tls.crt`, `tls.key` | Ingress TLS |
| `jama-smtp` | If `smtp.enabled` and `smtp.auth` | `smtp.existingSecret` | `username`, `password` | Outbound email |
| `jama-saml` | If SAML SSO | `sso.saml.metadataExistingSecret` | `metadata.xml` | IdP metadata |
| `jama-oidc` | If OIDC SSO | `sso.oidc.existingSecret` | `clientSecret` | OIDC client secret |

## Generated by the chart (optional)

- If `imagePullSecret.create=true`, the chart builds a `dockerconfigjson` Secret
  from `imagePullSecret.{registry,username,password,email}`. Prefer an
  externally-created pull secret in production so credentials stay out of values.

## Rules

- **Never** commit real license files, passwords, tokens, private keys, or
  `.dockerconfigjson` with real auth.
- For GitOps, encrypt at rest (Sealed Secrets / SOPS) or sync from a manager
  (External Secrets Operator). See `manifests/operator-secrets/README.md`.
